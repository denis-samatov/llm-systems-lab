# llm-systems-lab

**Distributed training and LLM inference internals, implemented from scratch, tested for
equivalence, and measured - with every number regenerated by one script.**

| | |
|---|---|
| **What** | A 5.5M-parameter Llama-style model trained single-device, with DDP and with FSDP2; crash-safe resharding checkpoints; and a serving engine with paged KV cache, continuous batching (vLLM-V1-style token budget, chunked prefill, preemption), prefix caching, speculative decoding and int8 quantization. |
| **For** | ML-systems / LLM-infrastructure engineers and interviewers who want to see mechanisms, not framework calls. |
| **Proof** | 35 tests incl. real multi-process runs: single == DDP == FSDP2 weights (max abs diff 7e-6 vs 3e-2 for a different batch), bitwise-identical crash/resume, torchrun worker restart, 2->1 and 2->4 rank resharding, engine outputs identical to a no-cache reference under every optimization, mutation-checked. |
| **Hardware** | Everything here ran on a 4-core Xeon VM **without a GPU**. CPU multi-process runs prove semantics; they are not multi-GPU performance. GPU harness for vLLM/SGLang is in [`gpu/`](gpu/README.md) and has **not** been run. |

## Quick start

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e '.[dev,lora,tracking,report]'
llmlab data download                       # RuMedTop3 complaints (CC BY 3.0), SHA-256 verified
llmlab train configs/tiny.yaml             # seconds
torchrun --nproc_per_node=2 -m llmlab.cli train configs/tiny.yaml -o name=fsdp -o parallel.mode=fsdp2
pytest -q                                  # 35 tests, ~3 min on 4 cores
scripts/reproduce.sh                       # every result in results/ (~1.5 h on 4 cores)
```

## Results (CPU, measured)

Full tables and figures: [`results/REPORT.md`](results/REPORT.md), generated by `llmlab report`
from the JSON files in `results/` (each with a manifest: packages, hardware, git commit, config).

**Training modes, same global batch (16 x 128 tokens), 30 steps**

| run | ranks | tokens/s | params+grads+Adam per rank |
|---|---:|---:|---:|
| single fp32 | 1 | 5,941 | 83.6 MiB |
| single bf16 (AMX) | 1 | 6,184 | 83.6 MiB |
| DDP | 2 | 4,750 | 83.6 MiB |
| FSDP2 | 2 | 2,996 | 41.8 MiB |
| FSDP2, no reshard after forward | 2 | 3,530 | 41.8 MiB |
| DDP | 4 | 5,253 | 83.6 MiB |
| FSDP2 | 4 | 3,479 | 20.9 MiB |

FSDP2 per-rank state scales as 1/N exactly (tensor byte counts). On one 4-core host, splitting
the batch across processes does not speed training up; DDP beats FSDP2 because FSDP2 adds
all-gathers on the forward path. Disabling reshard-after-forward recovers ~18% of FSDP2's
throughput at the cost of keeping full parameters during backward.

**Serving engine on the trained target model (fp32, 64 requests, dev prompts)**

| system | output tok/s | TTFT p50 | KV memory |
|---|---:|---:|---:|
| no KV cache, sequential (8 requests) | 111 | - | - |
| KV cache, sequential (8 requests) | 238 | - | - |
| static batching, B=8 | 848 | 2.44 s | 8.4 MiB reserved |
| continuous batching, 8 seqs | 1,039 | 2.06 s | 5.0 MiB peak used |
| continuous batching, 32 seqs | 1,568 | 0.19 s | 17.3 MiB peak used |

* **Prefix caching** (48 requests sharing a 64-token system prompt): prefill tokens computed
  3,798 -> 1,158 (-70%), TTFT p50 0.469 -> 0.286 s, throughput 753 -> 1,083 tok/s.
* **Speculative decoding** (2-layer draft, batch 1): greedy outputs identical to the target
  on 16/16 prompts for every k; best speedup **1.40x at k = 2** (acceptance 0.62). The draft
  costs 41% of a target step on CPU (overhead-bound tiny models), which caps the gain.
* **Load test** (Poisson arrivals, max 16 seqs): delivered throughput rises to ~1,450 output
  tok/s at 64 req/s and then plateaus; TTFT p95 goes 0.018 s -> 0.13 s -> 0.64 s -> 1.78 s at
  16 / 32 / 64 / 128 req/s while TPOT stays bounded (~10 ms): the saturation knee.
* **Quantization**: dev perplexity fp32 24.33, bf16 24.33, int8 weight-only 24.33, dynamic
  int8 24.86. bf16 prefill is 2.9x faster (AMX on this Xeon) but batch-1 decode is slower;
  int8 without fused kernels is slower than fp32 - see [ADR-C4](docs/adr/ADR-C4-quantization-variants.md).

**Fine-tuning on a downstream task** (ICD-10 coding, RuMedTop3 test n = 822, epoch chosen on dev)

| method | test Hit@1 (95% CI) | Hit@3 | trainable params | Adam state | step time (isolated) |
|---|---:|---:|---:|---:|---:|
| TF-IDF + logistic regression | **49.5% (46.1-53.0)** | 73.2% | - | - | - |
| linear probe (frozen backbone) | 25.3% (22.4-28.3) | 43.4% | 27k | 0.21 MiB | 0.24 s |
| LoRA r=8 on q/k/v/o (PEFT) | 31.5% (28.3-34.8) | 52.8% | 113k | 0.86 MiB | 0.50 s |
| full fine-tune | 33.8% (30.8-37.1) | 56.7% | 5.5M | 42.0 MiB | 0.54 s |

The TF-IDF baseline matches the 49.0% measured independently in
[rumed-icd-llm](https://github.com/denis-samatov/rumed-icd-llm). LoRA recovers most of full
fine-tuning's gain with 2% of the trainable parameters and 49x less optimizer state, but on
this tiny CPU model it is barely faster per step: gradients still flow through every layer.
The tiny backbone stays far below TF-IDF; the point is the trade-off, not the accuracy.

## Bugs found by the tests (kept in the history on purpose)

* **torchrun restarts failed 4 of 6 times**: after a restart, rank 0 dialled rank 1's gloo
  port *from the previous attempt*. Fix: namespace store keys per restart attempt + finite
  process-group timeout -> 8/8 ([ADR-C6](docs/adr/ADR-C6-torchrun-store-namespacing.md)).
* **FSDP2 eval hang** when `eval_batches < world_size`: ranks ran different numbers of
  forwards (each forward is a collective). Fixed with weighted dummy batches.
* **Engine livelock** when blocks leak: the scheduler spun forever. It now raises
  `NoFreeBlocks` on zero progress; a mutation test leaking one block per request fails loudly.
* **Weak end-to-end tests**: a random-init model barely uses attention, so removing the
  causal mask passed 11/12 tests. The fixture now amplifies attention and a guard test
  checks context sensitivity; the same mutation fails 5 tests.
* **Overfitting**: the corpus has 211k train tokens; 1,500 steps took dev loss from 3.39 to
  3.96. The budget was cut to 500 steps, chosen on dev loss (test never used).

## Limits

* No GPU: no NCCL, no CUDA kernels, no Nsight profiles, no vLLM/SGLang numbers.
* Tiny model and corpus; quality numbers illustrate trade-offs, not achievable quality.
* Benchmarks are single runs on one shared VM; small differences (< ~10%) are within noise.
* The paged-attention gather is a readable PyTorch reference, not a fused kernel.
